سیستم مدیریت فروش، خرید، انبار و صندوق برای کافه/فروشگاه، ساخته‌شده با **Django + HTML/CSS/JS** و رابط کاربری **بروتالیست فارسی**. فقط دو نقش «مدیر» و «اپراتور» اجازه‌ی ورود دارند.

## اجرای سریع (محیط توسعه)

پیش‌نیاز: Python 3.12+ (این نسخه با Python 3.14 و Django 6.1 تست شده است).

```bash
cd hesabeshkon/home
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py migrate --database=accountant

# ساخت مدیر و اپراتور (رمزها را عوض کنید)
python manage.py bootstrap \
  --admin-email admin@shop.local --admin-password 'یک-رمز-قوی' \
  --operator-email operator@shop.local --operator-password 'یک-رمز-دیگر'

# اگر می‌خواهید برای آزمایش داده‌ی نمونه بسازید:
python manage.py seed_demo

python manage.py runserver 127.0.0.1:8000
```

سپس در مرورگر: <http://127.0.0.1:8000/accounts/login/>

ورود با **ایمیل** و رمز عبور انجام می‌شود. در حالت `DEBUG=True` فایل‌های استاتیک توسط `runserver` سرو می‌شوند.

### اجرای تست‌ها

```bash
python manage.py test --settings=home.test_settings
```

خروجی مورد انتظار: `Ran 61 tests ... OK`

### ساخت داده‌ی نمونه


## کلیدهای میانبر (صفحه‌ی فاکتور)

| کلید | کار |
|------|-----|
| **F6** | ذخیره‌ی پیش‌نویس؛ در دیتابیس ذخیره می‌شود، موجودی تغییر نمی‌کند و بعداً از لیست «ادامه» می‌زنید. |
| **F7** | نهایی‌سازی: موجودی کم می‌شود، فاکتور قفل می‌شود و در دیتابیس حسابدار ثبت می‌گردد. |
| **F8** | ساخت کالای جدید یا ویرایش کالای ردیف فعلی (مودال سریع). |
| **F9** | نهایی‌سازی + رفتن مستقیم به چاپ بدون هیچ سؤال/تأییدی. |
| **Enter** | در کادر جستجو: افزودن کالای دقیقاً منطبق با بارکد یا اولین نتیجه. |
| **🎤** | افزودن کالا با صدا: «سه تا کاپوچینو اضافه کن». |

## دیتابیس حسابدار

فاکتورهای نهایی‌شده در یک **فایل SQLite جداگانه** (`accountant.sqlite3`) ثبت می‌شوند تا حسابدار به داده‌ی عملیاتی دست نزند و فقط اسناد نهایی را ببیند.

- ارسال در همان لحظه‌ی F7/F9 انجام می‌شود.
- اگر دیتابیس حسابدار آماده نباشد، فاکتور همچنان نهایی می‌ماند اما `accounted=False` می‌شود و در تنظیمات دکمه‌ی «ارسال دوباره» فعال است.
- ابطال فاکتور، رکورد حسابدار را `void` می‌کند (حذف نمی‌کند تا سابقه بماند).
- میگریشن جداگانه لازم دارد:

```bash
python manage.py migrate --database=accountant
```

نام فایل با متغیر `ACCOUNTANT_DB_PATH` قابل تغییر است.

## OCR فاکتور خرید

مسیر: **خرید → OCR فاکتور** یا `/faktor/buy/ocr/`

1. عکس یا PDF فاکتور را می‌فرستید (حداکثر ۱۲ مگابایت، PDF تا ۳ صفحه).
2. خواندن متن به دو صورت انجام می‌شود:
   - **مدل بینایی (پیشنهادی):** اگر `OCR_VISION_API_KEY` و `OCR_VISION_MODEL` تنظیم شده باشند، عکس مستقیماً به یک مدل چندوجهی سازگار با OpenAI می‌رود و خروجی ساختاریافته (JSON) می‌آید. این حالت روی فاکتور حرارتیِ فارسی و دست‌نویس بسیار بهتر از Tesseract است.
   - **Tesseract:** اگر کلید تنظیم نشده باشد یا سرویس خطا بدهد، همان مسیر قبلی با `tesseract` (فارسی/انگلیسی) استفاده می‌شود.
3. هر ردیف از **فیلتر حسابی** می‌گذرد: `وزن × فی = جمع ردیف` و `مجموع ردیف‌ها = جمع کل چاپ‌شده`. خطاهای رایج OCR (مثل کم/زیاد شدن یک صفر) خودکار اصلاح و علامت‌گذاری می‌شوند؛ اگر جمع جور نشود، فاکتور «نیاز به بازبینی» علامت می‌خورد و اطمینان پایین گزارش می‌شود.
4. ردیف‌های **وزنی** (مثل `۰/۵۹۰ کیلوگرم × ۲۳۰٬۰۰۰`) به‌صورت «۱ بسته با مبلغ همان ردیف» ثبت می‌شوند تا جمع فاکتور با مبلغ چاپ‌شده یکی بماند.
5. ردیف‌ها در صفحه‌ی بازبینی **قابل ویرایش** هستند (نام، بارکد، تعداد، قیمت خرید).
6. با تأیید شما:
   - کالای موجود با بارکد یا نام پیدا و به‌روز می‌شود؛
   - کالای ناشناس با درصد سود پیش‌فرض ساخته می‌شود؛
   - موجودی زیاد می‌شود؛
   - فاکتور خرید نهایی + رکورد حسابدار ثبت می‌گردد.

هیچ داده‌ای قبل از تأیید شما نوشته نمی‌شود. اگر عکس تار بود، از کادر **متن دستی** استفاده کنید.

### فعال‌کردن مدل بینایی

```bash
# نمونه برای OpenAI (یا هر سرویس سازگار: OpenRouter، vLLM، Ollama، LM Studio)
export OCR_VISION_BASE_URL="https://api.openai.com/v1"
export OCR_VISION_API_KEY="sk-..."
export OCR_VISION_MODEL="gpt-4o-mini"

# نمونه‌ی محلی با Ollama
export OCR_VISION_BASE_URL="http://127.0.0.1:11434/v1"
export OCR_VISION_API_KEY="ollama"
export OCR_VISION_MODEL="qwen2.5vl:7b"
```

بدون این متغیرها هیچ چیز تغییر نمی‌کند و سیستم مثل قبل با Tesseract کار می‌کند. کد مربوطه در `faktor/vision.py` (ارتباط با مدل) و `faktor/receipt.py` (پارس و اعتبارسنجی) است.

### تست از خط فرمان (بدون نوشتن در دیتابیس)

## صدا (میکروفن)

از `Web Speech API` مرورگر استفاده می‌شود و به سرور وابسته نیست.

- Chrome یا Edge لازم است.
- روی VPS باید سایت با **HTTPS** باز شود؛ مرورگرها در HTTP غیرلوکال اجازه‌ی میکروفن نمی‌دهند.
- عبارت‌هایی مثل «سه تا کاپوچینو»، «پنج عدد کیک» یا «لاته» را تشخیص می‌دهد؛ اگر کالا پیدا نشود، فرم ساخت کالا با همان نام باز می‌شود.

## تنظیمات (فقط مدیر)

مسیر `/settings/`:

## استقرار روی VPS (Nginx + Gunicorn)

### ۱) بسته‌های سیستم

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip nginx tesseract-ocr tesseract-ocr-fas poppler-utils sqlite3
```

### ۲) کاربر و مسیر

```bash
sudo useradd -m -s /bin/bash hesab
sudo mkdir -p /var/www/hesabeshkon /var/lib/hesabeshkon /var/backups/hesabeshkon
sudo chown -R hesab:www-data /var/www/hesabeshkon /var/lib/hesabeshkon /var/backups/hesabeshkon
```

فایل پروژه را در `/var/www/hesabeshkon` قرار دهید (پوشه‌ی `home` و `deploy`).

### ۳) نصب و تنظیمات

```bash
sudo -u hesab bash
cd /var/www/hesabeshkon
cp .env.example .env
nano .env          # SECRET_KEY، دامنه، مسیر دیتابیس‌ها
cd home
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

set -a; . ../.env; set +a
python manage.py migrate
python manage.py migrate --database=accountant
python manage.py collectstatic --noinput
python manage.py bootstrap --admin-email admin@example.com --admin-password 'رمز-قوی'
python manage.py check --deploy
```

نکته: `DJANGO_SECURE_SSL_REDIRECT=1` فقط وقتی درست کار می‌کند که دامنه با HTTPS بالا آمده باشد. برای تست موقت HTTP آن را `0` بگذارید.

### ۴) سرویس Gunicorn

```bash
sudo cp deploy/hesabeshkon.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hesabeshkon
sudo systemctl status hesabeshkon
```

### ۵) Nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/hesabeshkon
sudo ln -s /etc/nginx/sites-available/hesabeshkon /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d shop.example.com
```

### ۶) پشتیبان‌گیری

```bash
cd /var/www/hesabeshkon/home
. .venv/bin/activate
python manage.py backup_db --output-dir /var/backups/hesabeshkon
```

کرون روزانه:

```cron
0 3 * * * /var/www/hesabeshkon/deploy/backup.sh >> /var/log/hesabeshkon-backup.log 2>&1
```

## عیب‌یابی

| مشکل | راه‌حل |
|------|--------|

## محدودیت‌های فعلی / نقشه‌ی راه

- **تلگرام** عمداً پیاده نشده (خواسته‌ی خودتان)؛ دکمه‌ی «به زودی» دارد.
- OCR فارسی به نصب بسته‌ی زبان روی سرور وابسته است؛ خروجی همیشه نیاز به بازبینی دارد.
- ورودی بازه‌ی گزارش‌ها میلادی است (نمایش خروجی شمسی)؛ افزودن تاریخ‌گزین شمسی کار بعدی است.
- چاپ بارکد/برچسب قیمت به‌صورت تصویر مستقل هنوز اضافه نشده؛ بارکد در دیتابیس ذخیره و در فاکتور چاپ می‌شود.
- پرداخت آنلاین/درگاه بانکی در محدوده‌ی این نسخه نبوده است.
- SQLite برای یک کافه کافی است؛ در صورت رشد زیاد، مهاجرت به PostgreSQL توصیه می‌شود.

## تست دستی سریع

1. با مدیر وارد شوید.
2. یک کالا با بارکد خالی بسازید؛ ببینید بارکد خودکار ساخته می‌شود.
3. فاکتور فروش بسازید، F6 بزنید؛ در لیست، پیش‌نویس را ببینید و موجودی را بررسی کنید (نباید کم شده باشد).
4. همان پیش‌نویس را باز کنید و F7 بزنید؛ موجودی کم شود و در تنظیمات «حسابدار» همگام باشد.
5. F9 روی یک فاکتور جدید بزنید؛ مستقیم پنجره‌ی چاپ باز شود.
6. با اپراتور وارد شوید؛ گزارش‌ها و تنظیمات باید شما را به داشبورد برگردانند.
7. فاکتور خرید OCR را با یک عکس ساده یا متن دستی تست کنید.
